# 板卡及其型号变体

**本页涵盖：** 物理 CMP 170HX PCB：它由什么衍生而来、NVIDIA 刻意删掉了哪些器件、两个出货变体以及区分它们的一切可靠方法、板卡与部件编号、接口布局、VRM、跳线电阻阵列、按 SKU 的筛选结果，以及板上裸焊盘能告诉你什么、不能告诉你什么。

**先纠正两件事。**

1. **CMP 170HX 的 PCB 就是 NVIDIA A100 40 GB PCIe 参考设计，只是刻意删减了部分器件。** 板上每个元件位号都与泄露的 NVIDIA Tesla A100 电气原理图 `NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`（PG100/PG101 系列）对应。对应的是**40 GB PCIe** 板卡，不是 80 GB，也不是 SXM。
2. **正好有两个出货变体，它们解锁到不同容量。** **8 GB** 卡（`10de:20c2`）解锁到 **64 GB**。**10 GB** 卡（`10de:2082`）解锁到 **40 GB**。绝不要搞混。80 GB 配置曾在 10 GB 卡上尝试过，结果不稳定；见[80 GB 问题](../frontier/80gb.md)。

## 两个变体速览

| 属性 | 8 GB 变体 | 10 GB 变体 |
|---|---|---|
| PCI ID | `10de:20c2`（`0x20C2`） | `10de:2082`（`0x2082`） |
| 子系统 | `0x158510DE` | `0x155710DE` |
| 板卡部件号 | `900-11001-0108-000` | `900-11001-0105-000` |
| GPU 部件号 | `20C2-105-A1` | `2082-105-A1` |
| 板卡 ID | 未记录 | `0x8100` |
| 生产 VBIOS | `92.00.67.00.01`（2021-05-14） | `92.00.66.00.02`（2021-04-23） |
| HBM 供应商 | SK Hynix **HBM2e** | Samsung **HBM2** |
| 启用的 FBPA / FBP | 24 中 16 / 12 中 8 | 24 中 20 / 12 中 10 |
| 启用堆栈 / 总线宽度 | 4 个堆栈，4096 位 | 5 个堆栈，5120 位 |
| 原厂容量 | 8192 MiB | 10240 MiB |
| **解锁到** | **65536 MiB（64 GB）** | **40960 MiB（40 GB）** |
| 解锁后 CFG1 `0x009a0204` | `0x02779000` | `0x02669000` |
| 解锁后 LMR `0x00100ce0` | `0x0000020B` | `0x0000028A` |
| `FUSE_SKU_ID` `0x00821060` | `0x80` | `0x68` |
| `OPT_GPC_DISABLE` `0x00820350` | 观察到 `0x13`、`0x25`、`0x45` | 观察到 `0x15`、`0x85`、`0xa8`：**逐晶片，非按 SKU；全部留下 5 个 GPC / 70 个 SM** |
| `NV_PTOP_FS4` `0x0002241c` | `0x00000000` | `0x00000081` |

两者在显而易见的地方报告完全一致，这正是上表重要的原因：`lspci` 把两者都命名为 `GA100 [CMP 170HX] (rev a1)`，`nvidia-smi` 只把产品名报告为 "NVIDIA Graphics Device"。这两个字符串都无法区分 SKU。

第三个设备 ID `10de:20b0` 会被安装程序检测到，但**不解锁**：驱动内的门控只接受 `0x20C2` 和 `0x2082`，所以 `20b0` 卡只会装上工具而不会解锁任何东西。`10de:20b0` 是 A100 SXM4 40 GB 的 ID。

> [!CAUTION]
> **搞错变体是后果最严重的识别错误**
>
> 正式发布的驱动在运行时根据 PCI 设备 ID 选择几何配置，所以它自己会做对。但一个假设"8 GB 就是 40 GB"或"10 GB 就是 64 GB"的人，会读错每一条寄存器抓取、每一份容量报告和每一个排障帖子。每次先读设备 ID。

## 如何区分

### 从软件

```bash
# 1. 设备 ID 与子系统。这是权威答案。
lspci -nn -d 10de: | grep -i GA100
# 0d:00.0 3D controller [0302]: NVIDIA Corporation GA100 [CMP 170HX] [10de:20c2] (rev a1)

lspci -d 10de:20c2 -vnn | grep -i "Subsystem"
# Subsystem: NVIDIA Corporation Device [10de:1585]

# 2. 用 nvidia-smi 交叉核对。
nvidia-smi --query-gpu=pci.device_id,pci.sub_device_id,vbios_version,memory.total \
           --format=csv

# 3. 板卡与 GPU 部件号，以及序列号/板卡 ID，来自 InfoROM。
nvidia-smi -q | grep -Ei "board part number|gpu part number|inforom|serial"
```

映射：

| `pci.device_id` | `pci.sub_device_id` | 变体 |
|---|---|---|
| `0x20C210DE` | `0x158510DE` | 8 GB，解锁到 64 GB |
| `0x208210DE` | `0x155710DE` | 10 GB，解锁到 40 GB |

### 从寄存器（如果 PCI ID 存疑）

这些是经 BAR0 的只读探测。完整映射见[熔丝与 OTP](fuses-and-otp.md)，工具见[验证](../procedures/verify.md)。

| 寄存器 | 8 GB | 10 GB |
|---|---|---|
| `FUSE_FBP_DISABLE` `0x00820364` | `0x00000852` | `0x00000009`（也有 `0x840`；逐晶片而异） |
| `FUSE_FBPA_DISABLE` `0x00820368` | `0x00c0330c` | `0x000000c3`（也有 `0xc03000`） |
| `FBHUB_NUM_ACTIVE_LTCS` `0x00100800` | `0x10`（16） | `0x14`（20） |
| `FBPA_NUM_ACTIVE` `0x009a0164` | `8` | `0xa` |
| `FUSE_SKU_ID` `0x00821060` | `0x80` | `0x68` |
| `NV_PTOP_FS4` `0x0002241c` | `0x00000000` | `0x00000081` |
| VBIOS IFR 指纹 | `2ff19960f9175320` | `3ca3d24230d6800f` |
| VBIOS FIRMWARE 指纹 | `e2c91c1808ae2759` | `8c4e1344c51b0940` |

`NV_PTOP_FS4` 的第 0 位是 `GEN2_PCIE`，第 7 位是 `GEN2_PCIE_SPEED`，所以 8 GB 卡读 `0x00000000` 是更有意思的一半。10 GB 卡读 `0x00000081`，与 A100 80 GB、RTX 3070、GA10x 部件和 Drive `0x20bb` 的返回值一致。

### 从板卡与封装

| 信号 | 8 GB | 10 GB |
|---|---|---|
| 金手指上方的 PCB 丝印 | `180-11001-DAAA-B15`（也见过 `180-11001-DAAA-B35`、`180-11001-DAAA-045`） | 同一板卡系列 |
| ASIC 标记 | `GA100-105F-A1` | `GA100-105A-A1` |
| HBM 供应商（GPU-Z，或堆栈标记） | SK Hynix HBM2e | Samsung HBM2 |
| 板卡 PN 贴纸 / InfoROM `BRD` | `900-11001-0108-000` | `900-11001-0105-000` |

板卡部件号中的 `-0108-` 与 `-0105-` 字段，是不读 HBM 堆栈标记时最可靠的纯物理判别依据。

## 板卡编码与血统

| 编码 | 是什么 | 与 170HX 的关系 |
|---|---|---|
| `PG100` / `PG101` | NVIDIA A100 PCIe 板卡系列，170HX 位号所对应的原理图系列 | 170HX **就是**这块板，删减了器件 |
| `P1001-B02` | 具体的泄露原理图修订版（`NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`）；第 3 页是 "IO: PCIe CONNECTOR" | 通道宽度改造所用电容位号与参数的来源 |
| `180-11001-DAAA-*` | 170HX 上的 PCB 丝印部件号 | `11001` 字段与板卡 PN `900-11001-*` 共享 |
| `900-11001-0108-000` / `900-11001-0105-000` | 组装板卡部件号 | 8 GB / 10 GB |
| `GA100-883AA-A1` | 零售 Tesla A100 40 GB 的 ASIC 标记 | 全血统 bin，与 170HX 并排拍摄对比 |
| `GA100-105F-A1` | 170HX 的 ASIC 标记 | 阉割版 bin。`105` 与两个 SKU 的 GPU PN 后缀 `-105-A1` 一致 |
| `PG199` | NVIDIA DRIVE A100（A100D）**SXM2** 模块，PCI `10DE:20BB` | **不是 170HX 的板卡。** 完全是另一块部件 |

> [!WARNING]
> **PG199 是反复出现的混淆来源，有三种不同的混淆方式**
>
> 1. **PG199 不是 170HX 的板卡编码。** 它是 DRIVE A100 SXM2 模块。它被反复提为解锁候选，因为它与 170HX 共享显存拓扑（4 堆栈 Hynix HBM2e，4096 位，以 32 GB 出售，部分来源列出 40 GB SKU），而且不需要 PCIe 焊接。一位一手持有者报告它有 96 个 SM（而非 108），支持的核心时钟只有 1140–1260 MHz，PCIe 3.0 x16，散热极难，水冷下也难跑训练负载。TechPowerUp 给它列的 6144 位被认为是错的。不存在 PG199 解锁。有一例尝试在案：2026-07-26 有人把修改过的 cmpunlocker 用到一张 PG199 板卡上，预定的 CFG1 和 LMR 写入落位、PLM 打开，但引导以 `Booter failed 0x54` 失败，GSP 从未完成初始化。
> 2. **名为 `PG199` 的解锁器分支并不实现 PG199 支持。** 它与 master 的 diff 只触及 `README.md`、`common/constants.yaml`（仅注释）、`driver/build.sh`、`install.sh`、`remove.sh` 和 `requirements.txt`，还删除了 PR 模板。它的 profile 与 master 的 8 GB 和 10 GB profile 逐字节相同，驱动补丁一个没改，仓库里任何地方都找不到 `0x20BB`。它完全不做设备检测改动：master 自己的 `install.sh` 本来就在 `10de:20c2` 和 `10de:2082` 之外 grep `10de:20b0`，分支只是把 README 里的要求行改写了。
> 3. **TechPowerUp 条目 283106 是 DRIVE-PG199-PROD 镜像，绝不能刷进 170HX。** 见[VBIOS](vbios.md)。

## 物理尺寸与安装

| 测量项 | 值 |
|---|---|
| PCB 长度 | 27 cm |
| 全长 | 29 cm，含 I/O 挡板和插上的 EPS 接头 |
| 晶片周围的散热器螺栓孔位 | 57 × 68 mm（中心距）（68 mm 竖直，57 mm 水平） |
| 晶片封装 | 约 55 × 55 mm，BGA-2743 |
| 晶片面积 | 826 mm²，TSMC 7 nm，542 亿晶体管，65.6 M/mm² |
| 紧固件 | Torx T10 和 T15 |
| 导热垫 | 主要区域 1.5 mm 软垫，电感上 3 mm 软垫，晶片上另加液态导热硅脂 |

170HX 的封装铭文还写着 `NVIDIA / B KR 2120A1 / TBSG42.M0W e1`。

> [!NOTE]
> **开放问题**
>
> 主要区域的导热垫到底是 1.5 mm 还是 2 mm。1.5 mm 和 3 mm 的数据来自一位开过卡的持有者和一张照片；"2 mm"来自另一位参与者，前面加了"我觉得"。T10/T15 批头两边都确认。用卡尺量一张原厂垫就能定案。

散热、拆解顺序和水冷头安装见[散热](../operations/cooling.md)。这里值得重述的唯一板卡专属风险，因为它是*删减过的 PCB* 的属性，而不是某个散热器的属性：

> [!CAUTION]
> **放下水冷头之前，盖住每个未焊装的 IC 焊盘**
>
> 冷头接触柱可达范围内所有未焊装的 IC 焊盘都必须用导热垫盖住，否则冷头的金属柱可能跨接裸露的铜焊盘，永久杀死这张卡。**因为 170HX 是一块删减过的 A100 板，它的裸焊盘比真 A100 多得多，上水冷头也相应地危险得多。** 垫的位置：ASIC 左右两侧的 DrMOS 位；ASIC 的左下和右下；晶片右侧 PMIC（一颗电感与一颗电容之间）；以及晶片左侧、3.3 µH 电感下方的两颗 PMIC。指令与机制本身置信度高；因果归因建立在一张装水冷头约一小时后死掉的卡上，与既有的矿损故障竞争，从未被最终隔离。

## 接口布局

| 接口 | 详情 |
|---|---|
| PCIe 金手指 | 完整 x16 机械、**x16 电气布线**，原厂只能训练到 x4，因为 12 条通道的交流耦合电容被删减 |
| NVLink 金手指 | PCB 上**物理存在**，拆解照片可见，A100 水冷头会暴露出来。配套 NVLink IC 是否焊装**尚无定论，倾向缺件**：一份直接的 A100 对 CMP 对比说缺失，另一种基于原理图的读法说存在；见[NVLink 硬件](nvlink-hardware.md) |
| 供电 | **1 × EPS 8-pin**，不是 PCIe 8-pin，位于右上角，硬线从背板穿出 |
| 显示输出 | 无。没有任何显示硬件。显示输出被记录为永久缺失 |
| 未焊装的 4-pin 焊盘 | 实测带 12 V，疑为风扇接口 |

### EPS 接口

供电输入是单个 EPS 8-pin。大多数电源自带的 EPS 线卡扣过大、物理上插不进去，所以 2× PCIe-8-pin 转 EPS 的转接线是常见解法。顺带说明相关的线材安全规则：模组 EPS12V 线在**两端**都必须有 4× 12 V 和 4× GND，一根优质引脚大约只能承载 70 到 80 W。设备能力结构中的插槽供电上限是 75 W，接口额定 300 W。软件上限由 VBIOS 决定，不由接口决定：原厂固件最大 250 W，只有搭载 NVIDIA 300 W OC 镜像的卡才是 300 W。见[功耗与电源](../operations/power-and-psu.md)。

拆解时，必须先用塑料撬棒把电源线从背板上撬开，板卡才能移动；PCB 不能竖直抬起，因为 PCIe 连接器是滑进背板槽里的。这一步被记录为曾让某个知名硬件频道第一次尝试时犯迷糊。

> [!NOTE]
> **开放问题**
>
> 4-pin 风扇接口焊盘是否带电且支持 PWM 控制？一个引脚实测 12 V。配套插头部件号未知，也没人确认是否有转速或 PWM 信号。用示波器看空闲与负载下其余两个引脚，并在泄露的原理图上追踪它们，就能回答。它之所以重要，是因为这能实现无需外部控制器的独立单卡风扇控制。

## 删掉了什么，意味着什么

这是本页的核心。四类删减，后果截然不同。其中一类（NVLink 接口 IC）是"报告说删了"而非"确认删了"：焊装问题尚未解决，两边都有直接证据。

| 删减项 | 后果 | 可恢复？ |
|---|---|---|
| PCIe 交流耦合电容，通道 4–15（24 × 0402） | 链路只训练到 x4 而非 x16 | **可以。** 手工焊接，已可靠复现 |
| VRM 相位：DrMOS 晶体管及其输出电感 | 没人实测出任何影响 | 物理上可以，功能上无意义 |
| NVLink 接口 IC（焊装**未定**，见下文） | 无论怎样都没有 NVLink；熔丝把它关死 | 无已知路径 |
| 安全模块区域（Microchip CEC1712） | 170HX 有焊盘但没有芯片 | 不需要；它的缺失是*减少*了验证硬件 |

### PCIe 交流耦合电容：旗舰改造

卡只训练到 x4，是因为上方十二条通道（通道 4–15）的交流耦合电容**在 PCB 上有布线，但出厂时没焊**。每个差分对 2 颗 × 12 条通道 = 缺 24 颗 0402 器件。手工焊齐 24 颗恢复完整 x16 链路。只补 24 颗中的 12 颗得到 x8。该改造纯物理：不需要任何软件补丁就能生效。

| 规格 | 值 |
|---|---|
| 封装 | 0402 |
| 容值 | 220 nF（0.22 µF） |
| 介质 | **X7R**（经常被误写成 "XR7"） |
| 耐压 | ≥ 6.3 V。已知成功的 x16 改造用的是 6.3 V 器件 |
| 厂商部件 | Taiyo Yuden `MAASJ105SB7224KFCA01`（220 nF、6.3 V、X7R、0402）。Samsung `CL05B224KO5NNNC`（16 V）也报告可用 |
| 位号 | 大致 C1100–C1350，来自原理图第 3 页 "IO: PCIe CONNECTOR" |
| 分销商编号 | Digi-Key `3886834` 和 Digi-Key `1276-1176-1-ND` 都被引用过；两者未经互相验证。请引用厂商部件号 |
| 报告的替代品 | 100 nF 16 V X7R 对一位测试者有效；另有人从报废主板上拆下等效件 |

> [!CAUTION]
> **电容改造只改变通道宽度。它永远不改变 PCIe 代数。**
>
> 一张改了电容但没解锁的卡报告 **PCIe 1.0 下的 x16**。反过来，Gen2（5 GT/s）是在完全未改动的 **x4** 卡上用软件达成的。两个轴相互独立。这一点从源码即可定案：正式发布仓库或十二个未发布分支中的任何文件都不含 "capacitor"、"AC coupling"、"solder" 或任何通道宽度寄存器，对整个历史的 grep 也一无所获。实验性的 `Gen2` 分支只操纵链路**速率**。见[PCIe 子系统](pcie-subsystem.md)和[PCIe Gen2](../unlock/pcie-gen2.md)。

部分或桥接的焊接会协商到下一个合法宽度（16 到 8 到 4 到 1）而不是直接失败，所以报告的通道路数直接就是焊接质量的诊断指标。一位改装者跨三张卡的进步是 x4、然后 x8、然后 x16。电容改造后得到 x8 意味着焊接不完整或桥接，而不是独立的硬件上限。

返工技术、步骤、难度和实测带宽结果见[物理改造](../operations/physical-mods.md)。简短版：含铅 60/40 焊锡配凝胶助焊剂，先把工厂的无铅焊锡全部吸掉，约 380 °C 的细尖烙铁就够了，无需预热。该区域不局促，一位改装者手工完成一张卡约 20 分钟。整体烤箱预热有人提议过，随即被否决；新手最常见的失败模式是用红外炉加热风过度预热，导致 PCB 弯曲、内部走线断裂、芯片被烤熟，事后极难诊断。

### VRM 相位

卡使用 **MP86957 智能功率级，每个额定输出 70 A**。若干 DrMOS 位置及其输出电感未焊装。频道内的结论是原厂 VRM 大约能承受 500 W，未焊装相位是冗余而非必需。实测满载功耗约 250 W，即原厂上限。

> [!NOTE]
> **补齐缺失的 VRM 相位没有任何帮助**
>
> 从三个方向被驳斥。(a) 8 GB 卡有*完全相同*的供电，在 64 GB 下完全稳定，而 10 GB 卡在 80 GB 下不稳定。(b) 崩溃中的 80 GB 卡在崩溃负载下功耗从未超过约 80 W，而原厂上限是 250 W。(c) 电气上，GPU 不感知 VRM 相位数量；VRM 装一半 MOSFET 也能在满载下正确工作（其余只是更热）；而且 PWM 控制器还必须重新配置才能驱动新增相位，所以光焊器件连有效相位数都提不上去。500 W 这个数字是数据手册推理，从未用真实的 500 W 运行验证过。

恢复完整 A100 TDP 预计是简单的分流电阻改造而不是固件改动，但没人做过或测过。软件或 VBIOS 途径到 400–500 W 上限的提议也被提出过，同样从未实现。

> [!NOTE]
> **开放问题**
>
> 170HX 是否需要 PCB 背面核心附近的中型 SMD 电容，大约左右两排电容各对应每颗 MOSFET 两颗？这个问题来自一张照片，拍摄者之前见过一张 RTX 2070 掉了两颗这种电容，结果电压全乱；双排布局是冗余的，但至少一颗必须存在且工作。这涉及局部去耦而非 VRM 相位，所以与上面的相位数结论是张力关系，而非被它驳斥。从未在 170HX 上检查过。下一步：给一张工作正常的 8 GB 和一张工作正常的 10 GB 卡背面拍照，与原理图的 C 位号清单对比。

### NVLink

金手指存在。配套 IC 是否焊装**尚无定论，倾向缺件**：一次拆解和那一次直接的 A100 对 CMP 板卡对比都报告缺件，而基于原理图的读法和项目 VBIOS 对比表的一行（说 PCB 完全焊装）持相反意见；见[NVLink 硬件](nvlink-hardware.md)。
与此独立的是，NVLink 在硅片层被熔断关闭（`FUSE_NVLINK_DIS`），`0x00823800`–`0x0082382C` 功能覆盖块中没有任何 NVLink 寄存器，任何分支中也没有 NVLink 代码。`PTOP_SCAL_NUM_NVLINK` `0x0002246c` 仍然读 `0xc`，因为晶片是完整的 GA100。此卡没有 P2P。

相比之下，CMP 90HX 的导流罩留了 NVLink 接口的开孔，但 PCB 上根本没有连接器，所以 170HX 在这里算慷慨的：走线是有的。

> [!NOTE]
> **开放问题**
>
> NVLink 能救回来吗？频道内的预期是"多半需要 PCB 改造，补上缺失的器件"。复杂之处在于一种假说：GA100 的中介层本身可能带 eFuse，意味着 NVLink 断开可能是物理性的，任何激光或焊锡都够不着。没有人给中介层拍过片或探测过。这是这张卡上最难处理的硬件问题：很可能在未知之上还需要 BGA 级返工。见[NVLink](../frontier/nvlink.md)和[NVLink 硬件](nvlink-hardware.md)。

### 缺失的安全模块

一些 A100 板卡上存在、而 170HX 上没有的一块焊装区域，被识别为 **Microchip CEC1712 安全芯片**，最初被描述为"验证 VBIOS 的神秘 FPGA"，当天即被更正，并引用了 NVIDIA 面向最终客户的 "Data Center CEC Defeaturing"（数据中心 CEC 去功能化）通知。170HX 的 PCB 有焊盘但没有芯片。也不是所有 A100 都带它：一个 Ampere 修订版因器件短缺出货时就没有，而且从列表上无法分辨。AMD MI50 有一块类似的门卫芯片，只接受官方 VBIOS 镜像。中置信度：从未从板上读出任何部件标记，也没有拿出数据手册。

### 流传硬件恢复 PDF 中的 Winbond 芯片

流传的 `a100-unlock.pdf` / `cmp-170hx_a100_hardware-restore.pdf` 物料清单里出现的 Winbond BIOS 芯片，是一颗**备用 VBIOS 芯片**，用于从刷坏状态恢复。它不属于 PCIe 或显存解锁的一部分。PDF 作者说，x16 只需要 PCIe 通道上的小器件，构建里的其他一切都是为了在内部复刻 A100。一位读过同一份指南的经验丰富的改装者判断，它暗示需要钢网的全套 BGA 作业——这正是这份指南把一项其实新手到爱好者级别的改造吓退人的原因。中置信度：这基于对作者解释的二手转述，与作者本人"只需要通道器件"的说法一致。

## 跳线电阻

板卡在左上角去耦电容附近带了五对跳线电阻：五个跳线十个焊盘，器件无标记，通常为 100 kΩ 0402，拉向 0 V 或 1.8 V。每个跳线是一颗电阻加一个空焊盘，把器件在两个位置之间移动就翻转该跳线位。按 PCB 上从左到右：

| 跳线 | 位号 | 功能 |
|---|---|---|
| Strap1 | R986、R987 | `RAMCFG[1]` |
| Strap0 | R989、R990 | `RAMCFG[0]` |
| Strap3 | R993、R994 | `VGA_DEVICE` |
| Strap4 | R999、R1000 | `PCIE_CFG` |
| Strap2 | R1004、R1005 | `RAMCFG[2]` |

R1004 和 R1005 是*同一个*跳线位置的两个替代焊盘，不是两颗独立电阻。同一来源还提到第六个跳线 `DEVID_SEL`（R240/R241），但从未在物理板上定位到。

原厂模式：A100 40 GB 与 170HX 10 GB 共享 `LLLLH`；170HX 8 GB 是 `HHLLH`。跳线电阻 2（`RAMCFG[2]`，最右）在两个变体上都是 H。A100 原理图的 GPU STRAP CONFIGURATION 表把 STRAP2/STRAP1/STRAP0 对应到 `RAMCFG[4:0]`：`H, L, L` = `00100` = Samsung HBM2 8 Gb 8Hi；`H, H, H` = `00111` = Hynix HBM2E 16 Gb 8Hi；`L, M, H` = `01010` = Micron HBM2E 16 Gb 8Hi，其中 M 是中间电平三态。中置信度：这来自 VBIOS 跳线表和 A100 原理图，而非在 CMP 上实测。

> [!CAUTION]
> **移动显存跳线电阻不会解锁显存，而且有一种模式会砖掉卡**
>
> 从四个独立方向定案。(a) 一位测试者在 10 GB 卡原厂 VBIOS 下穷举了最后三个跳线的全部 8 种组合，报告显存没有任何变化；`LLHHH` 模式把系统砖掉、无 POST；物理拆掉三颗跳线也毫无变化。(b) 第二位测试者独立报告拨动跳线"什么都没变"。(c) 一张 10 GB 卡重新跳线为 `HHLLH`（8 GB 原厂模式）后，`FBPA_CFG1_BROADCAST @ 0x009a0204` 仍然读 `0x02449000`——未改动的 10 GB 值。(d) 一张未改动的 10 GB 卡达到了与重跳线卡相同的 80 GB 状态，所以任何电阻改动从来都不是前提。维护者在演示当天就接受了这一辟谣。

它不可能工作的原因就在源码里：正式发布的解锁在**驱动运行时根据 PCI 设备 ID** 选择内存几何配置，而不看任何跳线。补丁计算 `devId = pGpu->idInfo.PCIDeviceID >> 16`；如果 `devId == 0x20C2`，就写入 `cfg1Value = 0x02779000` 和 `lmrValue = 0x0000020B`，否则写入 `0x02669000` 和 `0x0000028A`，通过 `GPU_REG_WR32(pGpu, 0x009a0204U, cfg1Value)` 和 `GPU_REG_WR32(pGpu, 0x00100ce0U, lmrValue)`。因此把 `RAMCFG` 重新跳线成 8 GB 模式并不能让 64 GB 路径作用到 10 GB 卡上。只有改设备 ID 才行，而设备 ID 不在 `RAMCFG` 跳线上。

读旧抓取时值得知道的一件记录在案的怪事：一张 10 GB 卡上不匹配的跳线改动产生了 `CFG1 = 0x4266a000`（预期是 `0x02669000`），只有前四个 FBPA 和一个堆栈启用。

> [!NOTE]
> **开放问题**
>
> Strap3（`VGA_DEVICE`，R993/R994）和 Strap4（`PCIE_CFG`，R999/R1000）到底做什么？这个问题在跳线图被贴出两次后的 2026-07-26 被提出，无人回答。`VGA_DEVICE` 跳线可能关系到显示输出启用，`PCIE_CFG` 跳线关系到链路配置——两者都是开放问题。有一个偶然数据点：一位本想移动 R1004 的测试者实际移的是 Strap4，把模式从 `LLLLH` 变成 `LLLHH`，报告显存无影响。PCIe 能力协商是否变化从未测量过。下一步：刻意重做该实验，在前后各抓一次 `lspci -vv` 的 LnkCap 和 LnkSta。

> [!NOTE]
> **开放问题**
>
> 在物理板上定位 R240/R241（`DEVID_SEL`）。它很重要，因为设备 ID 是正式发布驱动选择几何配置的依据，也因为 `OPT_DEVID_SW_OVERRIDE_DIS` `0x00820584` = 1 关死了所有软件路径。已尝试并被否定的方法：在 R986–R1005 组附近目视搜索、正面照片搜索、以及询问一个商业 AI 助手（它编造了一个自信的答案，被质疑后又完全改口）。一位研究者根据位号编号论证 R240/R241 不可能靠近 R986–R1005，可能在 PCB 反面，并指出 A100 和 170HX 正面位号低于 500，而 Tesla V100 反面高于 500。另一位坚持他们拍到的 M 标记电阻就是。从未定案。最佳下一步：对低于 500 位号的那一面做系统性的高分辨率扫描，按泄露原理图的 `DEVID_SEL` 网络交叉对照，而不是按位号邻近关系。

## 显存封装

| | 8 GB 变体 | 10 GB 变体 |
|---|---|---|
| 供应商与类型 | SK Hynix HBM2e | Samsung HBM2 |
| GA100 封装选项 | 96 GB 更快的 Hynix HBM2e（同 A100 80 GB） | 48 GB Samsung HBM2（同 A100 40 GB） |
| 启用堆栈 | 4 | 5 |
| 总线宽度 | 4096 位 | 5120 位 |
| 解锁目标 | 4 × 16 GB = 64 GB，**稳定** | 5 × 8 GB = 40 GB，**稳定**；80 GB 不稳定 |

**这个供应商差异是"8 GB 到 64 GB 稳定而 10 GB 到 80 GB 不稳定"的主要解释。** 8 GB 卡用的是更密、更快的 Hynix 封装。高置信度：一个月内至少三位参与者独立断言、从未被反驳、有 GPU-Z 截图支持，并与观察到的稳定性差异一致。

完整晶片将是横跨 24 个 FBPA 的 6144 位。该配置从未在任何 170HX 上出现过。

> [!NOTE]
> **开放问题**
>
> 8 GB 卡带的是五个 16 GB 堆栈，还是六个堆栈（12 个 FBP 中四个被禁用）？流传的解锁指南称"HBM2e：物理 5 堆栈 × 16 GB = 64 GB（Hynix），软件锁到 8 GB"。概念验证团队称每个 GA100 封装带六个物理堆栈，8 GB 变体上是 96 GB Hynix HBM2e，其中两个 FBP 作为缺陷被熔断关闭、四个总共标记禁用，分布使两个堆栈跑完整 1024 位接口、四个只跑 512 位。两边都同意可寻址目标是 64 GB，都同意显存是 Hynix HBM2e。**倾向六堆栈说法：** 实测 8 GB 熔丝掩码在 12 个 FBP 中的 8 个上留下 24 个 FBPA 中的 16 个，而 5 × 16 = 64 的算术恰好贴合解锁目标，看起来像倒推出来的。但"两个堆栈 1024 位、四个 512 位"的分布与实测的连续逐 FBPA 死索引（2、3、8、9、12、13、22、23）并不能明显调和——那读起来像丢了*四个整堆栈*。开封、X 光或逐堆栈带宽测量能定案。

HBM 堆栈键合在**硅中介层**上，不在 PCB 上。因此失败的堆栈无法回流焊复活。一位成员用热风枪在多种温度下对几张 HBM2 GPU 花了几个小时，毫无成功。HBM 堆栈内部还含熔丝，因此有缺陷的 die 可以在堆栈内部被永久熔掉。特别是 Samsung HBM2 据报告不太耐受电压调整，而没人找到该供电轨的控制器或量过它的电压。

## 筛选：每个变体熔断了什么

容量和 SM 上限烧在熔丝里，软件无法重新启用。完整细节见[熔丝与 OTP](fuses-and-otp.md)；与板卡相关的摘要：

| 寄存器 | 8 GB（`0x20C2`） | 10 GB（`0x2082`） |
|---|---|---|
| `FUSE_FBP_DISABLE` `0x00820364` | `0x00000852`（12 个 FBP 中 8 个启用） | `0x00000009` 或 `0x840`（12 个中 10 个启用） |
| `FUSE_FBPA_DISABLE` `0x00820368` | `0x00c0330c`（24 个中 16 个启用） | `0x000000c3` 或 `0xc03000`（24 个中 20 个） |
| `FUSE_FBIO_DISABLE` `0x0082036c` | `0x00c0330c` | `0xc03000` |
| `ROP_L2_DISABLE` `0x008202C4` | | `0xc03000` |
| `FBHUB_NUM_ACTIVE_LTCS` `0x00100800` | `0x10`（16） | `0x14`（20） |
| `FBPA_NUM_ACTIVE` `0x009a0164` | `8` | `0xa` |
| 死亡的逐 FBPA 索引 | 2、3、8、9、12、13、22、23 | 0、1、6、7 |

被筛选掉的分区读回 `0xbadf20xx`（例如 fbpa02 `0xbadf2011`、fbpa08 `0xbadf2014`、fbpa12 `0xbadf2016`、fbpa22 `0xbadf201b`），而存活分区读 `0x00001000`。

跨卡对比转储时有两点需要注意：

- **没有真正的硅片缺陷，只有生效的禁用掩码。** 对应的 DEFECTIVE 寄存器全部读零：`FBP 0x8205CC`、`FBPA 0x8205D0`、`FBIO 0x8205D4`、`ROP/L2 0x8205E8`。往 DISABLE 寄存器写 0 不会移动它们。
- **具体掩码逐晶片而异；总数不变。** 10 GB 卡上观察到的 FBP 掩码包括 `0x840`（FBP6、FBP11）和 `0x00000009`（FBP0、FBP3）：索引不同，都留下 12 中的 10。观察到的 GPC 掩码包括 `0x13`、`0x15`、`0x25`、`0x45`、`0x85` 和 `0xa8`，都留下 5 个 GPC、都枚举 70 个 SM。不同卡之间看到这些值不同是正常的，不代表不同 SKU 或不同解锁潜力。

计算侧在两个变体上都处于熔丝下限：5 个启用 GPC、35 个启用 TPC、计算能力 8.0 下 70 个 SM，即 4480 个 CUDA 核心。每个逐 GPC 的 `CTRL_OPT` 寄存器（`0x00820838 + i*4`）和每个 `RECONF_OVR`（`0x00820A40 + i*4`）都读 `0x00000000`，`OPT_GPC_DEFECTIVE 0x008205C4` = 0，由 `OPT|RECONFIG` 计算出的熔丝下限与枚举数完全相等。相对完整 GA100（8 GPC × 8 TPC = 64 TPC = 128 SM），该部件出货晶片 SM 的 54.7%，缺失的 SM 没有一个可恢复。

晶片本身按所有规模寄存器看都是完整 GA100：

| 寄存器 | 值 | GA10x 对照卡 |
|---|---|---|
| `PTOP_SCAL_NUM_GPCS` `0x00022430` | `8` | `6` |
| `PTOP_SCAL_NUM_TPC_GPC` `0x00022434` | `8` | `4` |
| `PTOP_SCAL_NUM_FBPS` `0x00022438` | `0xc`（12） | `4` |
| `PTOP_SCAL_NUM_FBPAS` `0x0002243c` | `0x18`（24） | `4` |
| `PTOP_SCAL_NUM_LTCS` `0x00022454` | `0x18`（24） | `8` |
| `PTOP_SCAL_FBPA_PER_FBP` `0x00022458` | `2` | `1` |
| `PTOP_SCAL_NUM_NVLINK` `0x0002246c` | `0xc`（12） | `0` |
| `PTOP_FS_STATUS` `0x00022470` | `0x3f` | |
| `PMC_BOOT_0` `0x00000000` | `0x170000a1`（`0x170` = GA100，rev a1） | `0xb74000a1` |

> [!NOTE]
> **存档的寄存器地址更正**
>
> `0x00820C14` 是 `STATUS_OPT_FBIO`，**不是** `STATUS_OPT_FBPA`。FBPA 筛选状态在 `0x00820C18`。Pascal 时代的 FBPA 熔丝地址 `0x00021C14` 在 GA100 上返回 BADF。净室 `probe.sh` 同时带这两个条目并内联标注更正，所以工具本身保留了这段历史。

## 设备 ID 熔丝

两个 170HX PCI ID 都烧在同一颗晶片上。

| 熔丝 | 地址 | 10 GB 读数 | 8 GB 读数 |
|---|---|---|---|
| `OPT_PCIE_DEVIDA` | `0x008204d8` | `0x00002082` | `0x000020c2`（有争议，见下文） |
| `OPT_PCIE_DEVIDB` | `0x0082056c` | `0x000020c2` | `0x000020c2` |
| `OPT_DEVID_SW_OVERRIDE_DIS` | `0x00820584` | `0x00000001` | `0x00000001` |
| `OPT_INTERNAL_SKU` | `0x008203f4` | `0x00000000` | `0x00000000` |
| `OPT_SKU_ID` | `0x00821060` | `0x00000068` | `0x00000080` |
| `OPT_SLT_REV` | `0x008204bc` | `0x00000001` | |
| `FUSE_FB_FALCON_PRI_DIS` | `0x00820670` | `0x00000000` | |
| `FUSE_OPT_SECURE_GSP` | `0x0082074c` | `0x00000001` | |
| `FUSECTRL` | `0x00820000` | `0xe0040000` | |

`FUSE_FB_FALCON_PRI_DIS` = 0 意味着 Falcon 仍能触达 FB PRI 寄存器，这是显存解锁的前提。`FUSE_OPT_SECURE_GSP` = 1 意味着 GSP 调试被禁用。

**主 PCIe 设备 ID 熔断在晶片里，VBIOS 或跳线电阻都改不了；只有子系统 ID 可以由 VBIOS 设定。** DEVIDA 与 DEVIDB 之间的选择由跳线闩锁（`DEVID_SEL`），截至 2026-07-27 还没找到纯软件的办法来改变它。声明替代设备 ID 的 VBIOS 只意味着该 VBIOS 被*允许*运行在带那个 ID 的卡上；它不能重新命名这张卡。

> [!NOTE]
> **开放问题**
>
> 8 GB 卡上的设备 ID 熔丝值。2026-07-19 对一张 `0x20c2` 卡的 BAR0 探测报告 DEVIDA **和** DEVIDB 都是 `0x000020c2`。2026-07-22 的 PCIe 固件分析说 DEVIDA `0x2082`、DEVIDB `0x20C2`，2026-07-24/25 在 10 GB 卡上的转储与后者一致。两者都没有被撤回，且第二个数据背后的 SKU 未说明。要么 8 GB 卡确实两颗熔丝都在 `0x20c2`（另一个独立来源也这么声称），要么有一份转储贴错了标签。注意第一种读法打破了原本成立的 `DEVIDB = DEVIDA | 0x40` 假说——该假说在 170HX（`0x2082`/`0x20c2`）和一张 GA10x 对照卡（`0x2484`/`0x24c4`）上成立。从一张确认的 8 GB 卡上同贴 `lspci -nn` 一次性转出两颗熔丝，就能定案。

> [!NOTE]
> **`20B2` 不是 CMP 170HX 的设备 ID**
>
> 它出现在一条早期消息里，2026-06-29 在频道内被更正为 `2082` 的笔误。它也出现在一份推测性的重熔断提案里，作为*目标* A100 ID——那是另一种用法。170HX 的两个 ID 是 `0x20C2`（8 GB）和 `0x2082`（10 GB）。

## 修订差异

这张卡没有单一的"修订"轴。四个东西独立变化。

| 轴 | 见过的值 | 重要吗？ |
|---|---|---|
| 硅片修订 | 每张卡都是 `rev a1`（`PMC_BOOT_0` = `0x170000a1`） | 未观察到差异 |
| PCB 丝印尾字段 | `180-11001-DAAA-B15`、`180-11001-DAAA-B35`、`180-11001-DAAA-045` | 同一板卡系列；未建立任何功能差异。B15 和 B35 都做了 x16 电容改造且结果一致 |
| VBIOS 修订 | `92.00.67.00.01`（8 GB 生产）、`92.00.6D.00.09`（2021-11-01，300 W，无显存 OC）、`92.00.6D.00.0A`（2022-04-07，300 W，显存字段 432 MHz）、`92.00.66.00.02`（10 GB 生产） | **与解锁无关。** 与功耗上限和显存时钟有关 |
| 逐晶片筛选掩码 | 同一 SKU 的不同晶片，FBP 和 GPC 禁用掩码不同 | 无关：总数恒定 |

**VBIOS 版本对解锁是否工作没有任何影响。** 两台主机上的四张卡，`92.00.67.00.01` 和 `92.00.6D.00.0A` 各两张，解锁和 Gen2 结果完全一致，Board PN `900-11001-0108-000`、GPU PN `20C2-105-A1`、子系统 `0x158510DE` 也完全一致。把"8 GB 卡都带 `92.00.6D.00.0A`"当通用说法写是错的：现场两个版本都有。完整版本细节见[VBIOS](vbios.md)。

一个供应商侧的花絮值得记录，因为它会表现为明显的硬件差异：一个带有商业立场的来源声称手里有"两种 170hx 的 VBIOS，其中一种带宽更高"，没有给版本字符串和数字。这至少与 364 MHz 和 432 MHz 两种显存字段镜像都在流传这一事实一致。从记录上无法解决。

> [!NOTE]
> **开放问题**
>
> 提高功耗的"解锁 BIOS"卡在长期挖矿后会不会爆掉板背电容？一位持有者转述，卖他们卡的商家反复遇到这种情况，并展示了爆掉的板子，怀疑部件缩小到 8 GB 板背面的两颗电容。同一商家把卡跑在约 56 °C，让人怀疑他在监控错误的传感器，挖带宽密集型币种时把 VRM 烤过热。一位经验丰富的老玩家说从没见过这种故障并表示怀疑。没有故障器件的照片，也没有测量数据。一张可读位号的故障板照片，加上带宽密集负载下 VRM 的热电偶读数，就能定案。

## PCB 能告诉你什么、不能告诉你什么

**它能告诉你**确切删掉了哪些功能，以及——感谢匹配的 A100 原理图——确切哪些器件能恢复它们。通道宽度改造就是这样推导出来的：位号范围、封装、容值和介质全部来自原理图第 3 页，而不是猜的。

**它不能告诉你**任何关于容量或计算限制的信息。那些存在于三层，其中只有一层在板上：

| 层 | 位置 | 可移动？ |
|---|---|---|
| PCB 级物理缺失 | 板卡上 | 可以，靠焊接，但只对 PCIe 通道宽度 |
| VBIOS 固件 | SPI ROM，在 MAC 范围内 | 不行，没有 csecret(2) |
| OTP 熔丝 | 晶片上 | 不行 |

真正发布的解锁不移动其中任何一层。它在运行时从驱动覆盖寄存器状态，不做任何硬件改动。全部六个正式补丁在 `0x0082xxxx` 熔丝空间中写入的寄存器只有 `0x00823804`（FEAT PLM）、`0x0082381C`（SS0 = `0x88888888`）和 `0x00823820`（SS1 = `0x00000008`）。任何筛选寄存器（`0x00820350`、`0x00820364`、`0x00820368`、`0x0082036C`、`0x008202C4`、`0x00820C1C`）在任何地方都没有被写入。**解锁重新编程内存几何配置；它不能也不打算复活被熔断关闭的单元。**

### 板卡级死路

没有新信息就不要重试这些。完整清单见[死路](../history/dead-ends.md)。

| 尝试 | 为什么是死路 |
|---|---|
| 移动显存跳线电阻解锁显存 | 穷举全部 8 种组合没有产生任何容量变化；`LLHHH` 砖掉系统；拆掉三颗跳线也毫无变化 |
| 把 `RAMCFG` 重跳线成 8 GB 模式让 64 GB 路径作用到 10 GB 卡 | 驱动根据 PCI 设备 ID 选择几何配置，不看任何跳线 |
| 补齐缺失的 VRM FET、电容、线圈和电感稳定 80 GB | 三个方向被驳斥（见上文 VRM 一节） |
| 水冷头稳定 80 GB，因为零售 A100 80 GB 没有 IHS 而 170HX 有 | 从未测试，被显存刷新率解释取代，且被"崩溃卡只耗约 80 W"的测量削弱：它们不是热受限 |
| 硬件改装 HBM 电压轨作为稳定性修复 | 没人执行，没识别出控制器，没量过轨电压。Samsung HBM2 据报告不耐受，且故障 HBM 可在堆栈内部被永久熔除 |
| 用热风枪回流焊失败的 HBM2 堆栈 | 堆栈键合在中介层上而非 PCB。在几张 HBM2 GPU 上试了几个小时，无成功 |
| 一个 `strap5` 电阻在两个熔断设备 ID 之间切换 | 跳线从未被定位，一周后发布的五跳线图恰好枚举出五个跳线，没有 strap5 |
| 清除 `CTRL_OPT` 回收额外 SM | 全部八个逐 GPC `CTRL_OPT` 寄存器已经读 `0x00000000`，枚举出的 35 个 TPC 已经等于熔丝下限。GPC 禁用位于 `0x00820350` 的 OTP 中，不在 `CTRL_OPT` 里 |
| 对 CMP 级卡做 BGA 重植 | 亲自尝试过并失败：尽管 MODS 事后报告无错误，`nvidia-smi` 访问仍挂起。作为*故障模式*值得知道：一张 MODS 干净的卡仍可能挂住驱动 |
| 电容返工前把整板放烤箱预热 | 被否决为新手段陷阱；过度预热弯板、断内部走线、烤熟 IC |
| 给某些卡上找到的 "manufacturing_mode" 引脚加 3.3 V | 在真实硬件上观察到，但从未表征、从未追出结果 |

> [!WARNING]
> **编造的板卡拓扑读起来和真实板卡拓扑一模一样**
>
> 原文照录作为警示数据点。一个商业 AI 助手被问到 R240/R241 和板卡晶振在哪时，自信地把 R240/R241 放在"其他高值 100k 跳线电阻（如 R985–R1016）旁边"，把它们描述为接 `FS_OVERT` 和 `PCIE_CFG` 的 100 kΩ 0402 器件，并在 PG100/PG101 原理图的"第 5 页：CLOCK GENERATION / CRYSTALS"上点名 Y200（27.000 MHz）和 Y201（100.000 MHz 低抖动差分）。被质疑位号逻辑后它完全改口。其中没有一条可验证。任何不是从照片或原理图本身读出来的位号、页码或网络名，都视为未经验证。
