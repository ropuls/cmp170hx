# 热设计

## 本页涵盖

CMP 170HX 的散热器、硅片能承受的温度、驱动暴露的传感器，以及语料库中每个实测温度。这是参考页：要选实际的风扇或水冷头，见[散热](../operations/cooling.md)。同一问题的供电侧，见[功耗与电源](../operations/power-and-psu.md)和[供电](power-delivery.md)。

两个事实框住其余一切。第一，**散热器是全被动的**：裸散热片，没有风扇，没有驱动能看到的风扇接口，为 1U/2U 服务器机箱的强制气流设计。`nvidia-smi` 在贴出的每次抓取中都报告 `Fan Speed : N/A`，所以卡永远不会自己转起任何东西，在安静的桌面机箱里会很乐意把自己烤熟。第二，**这张卡很难加载**：常规 FP32 烤机在 250 W 的部件上只耗约 60 W，所以那样验证过的散热器等于没验证。

解锁在这里无关紧要。对正式发布解锁器和全部 12 个未发布分支做关键词扫描，`thermal`、`pstate`、`power_limit`、`vid_pwm`、`clkdomain`、`freqDelta`、`0x20340`、`MHz` 和 `watt` 在任何补丁、脚本或配置中都一无所获。下面每个热特性都是原厂板卡与原厂 VBIOS 的属性。

| 属性 | 值 | 依据 |
|---|---|---|
| 散热器类型 | 全被动裸散热片，无风扇，无罩风扇 | 直接观察 |
| 槽位宽度 | 双槽，约 40 mm / 1.57 in 厚 | 装支架的持有者实测，中置信度 |

| 晶片周围的散热器螺栓孔位 | 57 × 68 mm（中心距）（68 mm 竖直，57 mm 水平） | 直接测量 |
| 晶片封装 | 约 55 × 55 mm；晶片本身 826 mm² | 测量加晶片数据库 |
| 紧固件 | Torx T10 和 T15 | 拆解 |
| 主要区域的导热界面 | 1.5 mm 软垫 | 一位开过卡并带照片的持有者；另一位没把握地猜 2 mm |
| 电感上的导热界面 | 3 mm 软垫 | 同一来源 |
| 晶片上的导热界面 | 液态导热硅脂 / 液态导热垫 | 同一来源 |

40 mm 槽宽对支架选购很重要：为 A100、H100、A20、A30、A40 和 CMP 170HX 宣传的 A100/H100 风格 40 mm 鼓风机支架宽 1.57 in，因此适配标准双槽间距。

> [!NOTE]
> **开放问题：没人测量过这个散热器**
>
> 原厂 170HX 散热器的 CFM、静压、dBA 或鳍片间距数字，在这个语料库的任何地方都没有公布。本 wiki 里的每个风量数字都是对"风扇加卡"系统的社区测量，不是散热器规格。最接近锚点的是 `-pl 160` 下"四张卡两个 120 mm 风扇"的结果。要闭合它，需要一个人用已知风扇曲线，在固定功耗上限下把风扇工作点与稳态晶片温度关联起来。

## 热限制

前四个直接来自一张已解锁 10 GB 卡上的驱动（驱动 `610.43.02`，2026-07-25 18:32 抓取，P0，利用率 18%）。最后两行是社区观察，不是驱动报告。

| 限制 | 值 | 层级 |
|---|---|---|
| GPU 关机温度 | **98 C** | 硬件，驱动报告 |
| GPU 降速温度 | **95 C** | 硬件降速，驱动报告 |
| GPU 最高工作温度 | **85 C** | 驱动报告的工作上限 |
| 显存最高工作温度 | **95 C** | 驱动报告，HBM |
| 报告的降频起始 | **约 80 C** | 单一无出处读数，未贴遥测，低置信度 |
| GA100 显存降频（回忆） | 约 85 C，"不是所有 bios 都有" | 两条含糊的回忆，低置信度 |

那次抓取时卡读 GPU 34 C、显存 48 C、`Fan Speed : N/A`，每个时钟事件原因（包括 HW Thermal Slowdown 和 HW Power Brake Slowdown）都是 `Not Active`，每个事件计数器都是 `0 us`。

> [!NOTE]
> **开放问题：降频分层是推断而非确立**
>
> "什么时候降频"有四个数字在案：80 C（一位测试者自己的遥测）、85 C（两条 GA100 回忆和驱动的 Max Operating Temp）、95 C（驱动 Slowdown Temp）和"100 C 以上"（对一张散热完全失效的卡的描述）。这些可能在不同层级都是真的：80 C 处 VBIOS 级软性降时钟、85 C 处驱动工作上限、95 C 处硬件降速、完全没有散热回路时的失控。**没人贴过把时钟降低与温度关联起来的降频日志。** 能定案的是扫过 75–95 C 的记录日志：`nvidia-smi --query-gpu=temperature.gpu,clocks.sm,clocks_throttle_reasons.active --format=csv -l 1`。

### 社区设计目标

独立于驱动限制，测试者们收敛到**负载下核心 70 C、显存热点 75–76 C** 作为散热方案的设计目标。90 C 热点被视为不可接受，并成为否决单个 40 mm 风扇的依据。在定案那次交流中，一位选购风扇的参与者问 90 C 对芯片是否可以接受，然后报告读到降频从 80 C 开始，得到的回答是"绝对不行！"。80 C 数字旁没有贴遥测，所以请把它当读数而不是测量。

## 传感器与遥测

卡暴露 GPU 温度和显存温度，此外没有任何热数据。没有风扇转速计、没有逐堆栈 HBM 传感器、没有暴露的 VRM 或热点差值传感器、也没有 `nvidia-settings` 风扇控制路径，因为没有风扇。

```bash
# 静态限制与当前读数
nvidia-smi -q -d TEMPERATURE

# 持续日志，每秒一行，适合找真实降频点
nvidia-smi --query-gpu=timestamp,temperature.gpu,temperature.memory,clocks.sm,\
clocks.mem,power.draw,clocks_throttle_reasons.active --format=csv -l 1
```

确认在 170HX 上存在的字段：

| 字段 | 真实抓取中的确认值 |
|---|---|
| `GPU Current Temp` | `34 C`（空闲，已解锁 10 GB） |
| `GPU Shutdown Temp` | `98 C` |
| `GPU Slowdown Temp` | `95 C` |
| `GPU Max Operating Temp` | `85 C` |
| `Memory Current Temp` | `48 C`（空闲） |
| `Memory Max Operating Temp` | `95 C` |
| `Fan Speed` | 贴出的每次抓取都是 `N/A` |
| Clocks Event Reasons | 空闲时全部 `Not Active`；计数器全部 `0 us` |

`nvtop` 在一行里报告同样的传感器，也是大多数测试者贴出的格式：

```text
GPU 1440MHz MEM 1890MHz TEMP 76C FAN N/A POW 278 / 300 W
PCIe GEN 1@ 4x
GPU 100%  MEM 57.534Gi/64.000Gi
```

一位在构建风扇曲线的测试者给出的实用备注：用报告的**热点**传感器驱动曲线会让控制器来回找，**晶片温度是更好的控制输入**。

## 漏电反馈与热失控

GA100 存在真实的漏电驱动正反馈回路。结温更高意味着 CMOS 漏电流更高，漏电流更高意味着更多热量，更多热量意味着更多漏电。

对它最干净的测量是偶然得到的。一位研究者给一张卡装了水冷头但没有冷却液干跑：空闲功耗从约 **40 W** 起步，在 **80 C 时爬到 60 W**，断电时仍在上升。

> [!CAUTION]
> **装了但干着的水冷头，通电绝不要超过 5 分钟**
>
> 干冷头比没有更糟：它起隔热作用。实测 40 W 到 60 W 的爬升在 80 C 时还没有稳定。如果必须干装检查间隙，5 分钟内断电。

两个后果，一个无害一个有害：

- **无害：** 给卡更好的散热会降低它的空闲功耗，因为它既抑制漏电项又带走热量。这最可能是测试者之间 30 W 对 44 W 空闲差异的解释。
- **有害：** 如果散热彻底失效，GA100 不会停在降频点。一份来自 A100 级实操经验的描述："热降频在如此高的功耗下运行，如果散热失效，它会热降频，但降到 100 度以上的温度，然后消耗更多功耗，温度进一步升高……最后你会得到一座火山。" 确切温度依 BIOS 而定，同一场交流中有争议，所以请把曲线形状视为确立、数字视为未定。

### 风冷下的 HBM 下限

在一张 140 mm 导流罩配 120 mm 风扇 @ 3000 RPM 的卡上做了多配置功耗与时钟扫描后，一位测试者总结："调对了的话……温度基线就在这里……你能省瓦数，但风冷下你降不了温度"以及"风冷下拿到更低的 hbm 温度似乎不可能"。那些设置（`EFF / Balanced +300MHz / 1400`）下 30 分钟 `gpu_burn` 无错误完成。

> [!NOTE]
> **开放问题：HBM 温度下限是散热限制还是内在的？**
>
> 一次直接索取水冷头 HBM 温度数据的请求无人回应，所以下限从下面是无界的：没人知道水能否把 HBM 实质性地降到比风冷更冷。这个领域最便宜的高价值实验，是让平价水冷头的持有者（一小时核心 48 C / 显存 58 C）记录显存传感器重跑同一个 `EFF / Balanced +300MHz / 1400` 扫描。

## 散热通常不是瓶颈

这让人意外，也改变你该怎么为散热花钱。

- 把散热良好的卡功耗上限从 250 W 提到 300 W，在**核心与显存都低于 65 C** 时赢得 **+2.8%** BF16 吞吐（约 180 到 185 TFLOPS）。核心就是不想跑更高。
- 带 OC VBIOS 的 8 GB 卡上 `mmapeak` 停在 **1470 MHz，只耗约 150 W**，GPU-T 报告 `PerfCap: None`，即使功耗上限在 300 W。功耗和暴露的上限都无法解释那个天花板，它仍未解释。
- 80 GB 配置的不稳定性不是热也不是供电问题：崩溃负载下故障卡**从未超过约 80 W**。

确实存在一种真实的热故障模式。从未重新涂硅脂或换垫的卡可能严重降频：一位持有两张 8 GB 卡的玩家只能跑一张，因为第二张"降频很厉害"，需要换垫重涂。如果一张卡在相同气流下比邻居早得多地降频，先怀疑出厂导热界面，再怀疑硅片。

## 气流指导

没有实测需求，只有一组从上面测量中浮现的规则。它们被收集起来并在[散热](../operations/cooling.md)上与真实散热器对比。

| 量 | 值 | 状态 |
|---|---|---|
| 全功耗运行的静压目标 | 20 mm | 规格推导建议，**未实测** |
| Arctic P12 Pro CO 公布规格 | 约 7 mm 静压，130 m³/h | 厂商规格；这把风扇仍让四张卡在 `-pl 160` 下低于 65 C |
| 最小实用风扇功率 | 4 W 以上，即 12 V 下 0.35 A | 实用指导，未受挑战，未实测 |
| 首选风扇类别 | 径向高静压鼓风机，或 38 mm 厚轴流风扇 | 薄 120 mm 风扇在 300 W 和双卡场景被怀疑 |
| 气流方向 | **抽，不要吹** | 穿管导流罩吹风回喷的一致一手报告 |
| 单个 40 mm 风扇 | 任何转速都不够 | 1 × S4028-15K 给 90 C 热点；2 × 给 70 C / 76 C |

无论用什么散热器，**还必须给 VRM 散热**，不能只给晶片散热。去罩加压装塔式散热器用在晶片上，供电区域仍需要一把独立的 80–120 mm 风扇。那些器件在哪见[供电](power-delivery.md)。
