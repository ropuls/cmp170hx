# 项目时间线

## 本页涵盖

一份按日期记录的资料，讲述 CMP 170HX 如何从一张熔丝阉割的矿卡变成 64 GB、全速率的 GA100，覆盖活跃期 **2026-06-22 至 2026-07-28**，并包含使其成为可能的早期背景。聊天时间戳默认 UTC，除非标注了本地时区；精确到秒的时间是从消息 snowflake 解码或读取自 git 作者时间戳。git 行按**作者本地时区**（多为 `-07:00`）标注日期，这是提交自身的呈现方式；因此三个分支的 tip 在这里比其 UTC 时刻早一个日历日。

读者应锚定的五个里程碑：

| 日期 | 里程碑 |
|---|---|
| **2026-07-12** | 计算解锁在硬件上生效。一个手动的五步 TTY 流程解除 1/32 FP32 节流；测得 12.28 TFLOPS SGEMM |
| **2026-07-14 / 15** | `cmpunlocker` 公开。首个 release 是**免驱动的 Python** 计算解锁器，完全不改驱动 |
| **2026-07-18** | 显存几何解锁上线。8 GB 到 **64 GB**、10 GB 到 **40 GB**，驱动内完成，一天之内 |
| **2026-07-23 / 24** | 免驱动路径以独立 Python refire chain 回归，并宣布 **PCIe Gen2** |
| **2026-07-26 / 27** | Gen2 分支谱系稳定；在电容改装的卡上捕获到一次 Gen2 x16 观测 |

本时间线严格区分两件事，这也是整本 wiki 的规则：PCIe 链路**速率**（Gen1 到 Gen2，属于软件与固件解锁）与 PCIe 链路**宽度**（x4 到 x16，只能通过手工焊接 24 颗被移除的电容实现）。它们是在不同日期取得的不同的成就。参见 [PCIe 子系统](../hardware/pcie-subsystem.md) 与 [物理改装](../operations/physical-mods.md)。

## 2026-07-12 至 2026-07-17：计算落地，仓库公开

### 计算解锁

**2026-07-12** 是节流解除的日子。在任何驱动内补丁出现之前可用的手动流程：

```text
run the ROP script  ->  FLR  ->  kill the NVIDIA driver  ->  FLR again  ->  run the SM unlock script
```

FLR 指 `echo 1 | sudo tee /sys/bus/pci/devices/0000:${PCI}/reset`。它必须从 TTY 运行。驱动是 580.159.04 的开放内核模块，payload 由 `patch_gsp.py` 拼接进 `gsp_tu10x.bin`。`Guide_SM.sh` 将其实现为三写 ROP 阶段（CFG1 `0x02779000`、LMR `0x0000020B`、PLM `0xFFFFFFFF`）、一次 FLR、一次激进驱动卸载、第二次 FLR，然后通过 `resource0` 进行主机写 `0x0082381C = 0x88888888` 与 `0x00823820 = 0x00000008`，并带读回验证。

同一天测得：首次完整 SM 解锁上的 **12.28 TFLOPS SGEMM FP32**，由两名独立测试者报告。该卡该次会话没有采集锁定基线。与之同时宣布的"32x"是熔丝值 `0x5` 隐含的架构除数，所引用的约 0.38 TFLOPS 出厂速率是 12.28 除以 32，并非独立测量。一次独立测得的约 0.39 TFLOPS 锁定速率佐证了该除数；参见 [性能](../operations/performance.md)。原厂 `FEATURE_OVERRIDE` 块被完整 dump（`regs_01.txt`），主杀熔丝 `0x008203f0` 被确认未烧断、值为 `0x00000000`，这正是这一切之所以可能的理由。

为此付出了**超过 1100 次点火（fires）**，其中只有约 50 次是真正不同的尝试，正如做这项工作的人后来所说："我事先就是不可能知道这一点。"

## 里程碑总结

| 成就 | 日期 | 持久性 | 是否随 `master` 发货？ |
|---|---|---|---|
| FP32 FMA 编译期变通方案（约 16 倍，6.25 TFLOPS） | 2023-10-27 | 源码级，按应用 | 不是驱动功能 |
| 解除计算节流（SS0/SS1，全速率） | 2026-07-12 | 经受 FLR（常开岛） | **是** |
| `cmpunlocker` 公开，免驱动 Python | 2026-07-14 / 15 | 每次启动重新应用 | 2026-07-18 移除 |
| 显存几何，8 GB 到 64 GB、10 GB 到 40 GB | 2026-07-18 | **不能**经受 FLR 或断电 | **是** |
| 多卡支持 | 2026-07-18 / 19 | 每次启动 | 否，仅分支 |
| 10 GB 卡上的 80 GB | 2026-07-19 | 尝试过，约 40 GB 以上不稳定 | 否，也不应如此 |
| 免驱动 SEC2 refire chain（v1 至 v6） | 2026-07-22 至 24 | 每次启动，GPU 必须解绑 | 否，并行路径 |
| PCIe Gen2（速率，x4） | 2026-07-24 | 每次启动，分支上驱动内 | 否，仅分支 |
| PCIe x16（宽度，靠焊接） | 硬件改装，任意日期 | 永久，物理 | 非软件 |
| Gen2 x16 组合 | 2026-07-26，一次观测 | 未经证实 | 否 |

> [!CAUTION]
> **80 GB 档位不是里程碑**
>
> `80` 分支报告约 81920 MiB 与 85,545,582,592 字节，`cudaMalloc` 77 GiB 成功，但 80 GB 时触及超过约 40 GB 的内核会致命丢失 GPU，与功耗上限无关。报告的 Xid 码包括 Xid 31（被描述为无害）与 CUDA 内存测试后的 Xid 154；占主导的症状报告是挂起。只有旁观者建议过 Xid 31，持有故障卡的运营者并未佐证它是*那个*特征。`cuda_memtest` 除非限制在 39 GB 否则挂起。发货的是 40 GB。参见 [80 GB 问题](../frontier/80gb.md)。
