# 物理改装

**本页涵盖。** 所有有记录的 CMP 170HX 硬件改装：恢复 x16 链路宽度的 PCIe 交流耦合电容改装、让它成功的焊接技术和工具、如何验证结果、拆解顺序、散热与水冷头改装、电源接口情况、strap 电阻，以及在这张卡上任何烙铁都修不了的东西。

头条结论：**CMP 170HX 只协商到 PCIe x4，是因为它 16 条通道中有 12 条出厂时就没贴交流耦合电容。手工补焊 24 颗缺失的 0402 220 nF X7R 电容即可恢复完整的 x16 链路，不需要任何软件补丁。** 这是入门到爱好者级别的返工，手工操作每张卡约 20 分钟。

> [!WARNING]
> **宽度不是速度**
>
> 电容改装只改变**链路宽度**。它从不改变 PCIe 代数。改过电容但没装解锁器的卡报告 **x16 @ PCIe 1.0**。反过来，解锁器在任何卡上都给出 Gen2（5 GT/s），不管焊没焊过电容：只有没装解锁器的卡才报告 Gen1。这两条轴相互独立，绝不能混为一谈。速度那一半见 [PCIe Gen2](../unlock/pcie-gen2.md)。

## 为什么 16 条通道中有 12 条是死的

CMP 170HX 的 PCB 就是 NVIDIA A100 40 GB PCIe 参考设计，只是元件被故意删减了。板上每个位号（reference designator）都与泄露的 NVIDIA Tesla A100 电气原理图 `NVIDIA-A100-GA100-883-P1001-B02-Rev-A.pdf`（PG100/PG101 家族）对应。金手指上方的板面丝印在不同卡上分别是 `180-11001-DAAA-B15`、`180-11001-DAAA-B35` 和 `180-11001-DAAA-045`，同一家族、版本字段不同。见 [Board and variants](../hardware/board-and-variants.md)。

被删掉的有：未贴片的 VRM 相位、缺失的 NVLink 接口 IC、缺失的安全模块区域，以及关键的一点——**第 4 到第 15 条通道上缺失的 PCIe 交流耦合电容**。走线是布在 PCB 上的，缺的只是元件。NVIDIA 只贴了这张卡打算用的那 4 条通道。

这是板级删减，不是熔丝，也不是固件设置。所有被探测过的 170HX 上，PCIe 通道熔丝都是全清的：

| 熔丝 | 地址 | 170HX 值 | 含义 |
|---|---|---|---|
| `OPT_PCIE_LANE_DISABLE` | `0x00820394` | `0x00000000` | 没有通道被熔断关闭 |
| `CTRL_OPT_PCIE_LANE` | `0x0082082c` | `0x00000000` | 没有通道覆盖生效 |
| `STATUS_OPT_PCIE_LANE` | `0x00820c2c` | `0x00000000` | 硅片报告全部宽度可用 |

链路状态寄存器说的是同一件事。出厂 `lspci` 在 capability 中宣称 x16，却在 status 中协商降到 x4：

```text
LnkCap:  Port #0, Speed 2.5GT/s, Width x16, ASPM not supported
LnkSta:  Speed 2.5GT/s, Width x4 (downgraded)
LnkCap2: Supported Link Speeds: 2.5GT/s
```

宽度上的 `(downgraded)` 标记就是线索：端点能力是 x16，却训练成 x4——这正是 12 条通道上存在物理层不连续时会出现的情况。独立的佐证来自一张运行 Gen2 代码的出厂未改装 8 GB 卡，它报告 `LnkCap: Speed 5GT/s, Width x16`，而 `LnkSta: Speed 5GT/s, Width x4 (downgraded)` 仍然不变：软件移动了速率，却动不了宽度。一个本身是 x16 能力的主机端口仍然把这张卡训练在 x4。

### 替代元件

这项改装对 100 nF 到 220 nF 的通用去耦类别是宽容的。一位测试者报告用 `100 nF 16 V X7R` 元件成功了。另一位直接把报废主板上的同规格 0402 元件拆下来用。两者都是单一的一手报告。如果你有正确的 220 nF 元件，就用它：替代件的证据很薄，而且交流耦合网络勉强达标时会表现为一次训练失败，和焊得不好无法区分。

## 焊接技术

多位职业焊接人士裁定的共识，其中包括一次对相反立场的明确撤回。

| 参数 | 建议 | 置信度 |
|---|---|---|
| 焊料合金 | **60/40 含铅** | 高 |
| 助焊剂 | 凝胶助焊剂 | 高 |
| 预处理 | **先用吸锡带把出厂无铅焊料全部吸掉** | 高 |
| 烙铁温度 | **约 380 °C**，细尖头 | 高 |
| 预热 | **不需要** | 高 |
| 热风 | 可选，批量时更快，喷嘴尺寸要合适 | 高 |
| 镊子 | 陶瓷反头镊子，可以夹，但容易把 0.5 mm 元件弹飞 | 高 |
| 遮蔽 | 用 Kapton 胶带遮蔽周围区域 | 高 |
| 低温合金 | 可接受 | 中 |
| 练习 | 先拿废板练手 | 高 |
| 每卡耗时 | 手工约 **20 分钟**，有经验的改装者，效果不完美 | 中 |

几个人收敛出的工作流程：用吸锡带把焊盘对上的出厂无铅焊料吸干净，涂凝胶助焊剂，给一个焊盘上锡，用镊子放上元件并点焊固定这一侧，再流焊另一侧。用针管涂锡膏加热风枪可以让元件自对准，这是习惯热风的人更快的路线。

> [!CAUTION]
> **不要给整块板预热**
>
> 有人曾在频道里提议把整板放进烤箱预热，随即被否为新手陷阱。有记录的真实后果是过度预热（红外炉加热风）导致 **PCB 弯曲、内部走线断裂和 IC 烤坏**，产生事后极难诊断的隐性缺陷。这是这项返工中新手失败的主要模式。380 °C 细尖烙铁、不预热，就够了。

### 难度

这是常规 0402 返工。24 颗电容焊到金手指旁边板背上标好号、不拥挤的焊盘上。没有 BGA、没有重植球、没有钢网、没有固件步骤，也不需要编程。有经验的改装者称它是「大概是做 PCIE 改装最容易的卡」，比需要全套 BGA 设备的 CMP 100HX 改 V100 简单得多。手工每张卡约 20 分钟。

> [!NOTE]
> **如果你是收到报价请求的维修店**
>
> 整个活就是：在客户连料一起递给你、PCIe 边缘连接器旁边 `C1100`-`C1350` 组的空焊盘上，装 24 颗 0402 电容（220 nF、X7R、6.3 V 或更高）。先用吸锡带把出厂无铅焊料吸掉，再用含铅焊料。
>
> 没有诊断环节，没有坏的东西，你这边也没有固件或软件步骤。焊盘标着号、不拥挤、在外层表面。这活儿严格小于那些做了多年的 CMP 100-210 改装店——那个要搬 strap 电阻**还要**强制刷写；这个只有电容，别的什么都没有。
>
> 客户反馈说，找了十多家店都被拒，才找到一家愿意直接干活的。这才是这个流程的主要障碍，不是返工本身。

频道里还记录了一个单独警告：流传的 `a100-unlock.pdf` / `cmp-170hx_a100_hardware-restore.pdf` 物料清单里包含一颗 **Winbond 备份 VBIOS 芯片**和其他与通道改装无关的元件。一位读那份指南的有经验改装者合理地推断它意味着需要钢网的全套 BGA 活儿。其实不是。PDF 作者自己说过，x16 只需要 PCIe 通道上的那些小元件；清单里其他一切都是想尽可能在机箱里复刻一台 A100。

## 部分贴片与协商出的宽度

PCIe 宽度协商会回退到下一个合法宽度（16、然后 8、然后 4、然后 1），而不是直接失败。这让报告的通道数成为焊点质量的直接诊断指标。

| 正确贴上的电容数 | 训练出的宽度 |
|---|---|
| 0 / 24（出厂状态） | **x4** |
| 12 / 24 | **x8** |
| 12 到 23 / 24，或存在任何桥连/冷焊点 | **x8** |
| 24 / 24 | **x16** |

改装后得到 x8 意味着**焊接不完整或有桥连，不是另一个硬件限制**。一位改装者三张卡的进度是 x4、x8、x16，随技术提高。另一张卡在「做了几次小调整后」从 x4 到 x8 再到 x16。第三位测试者停在 x8，猜测链路需要活动负载才会加宽；证据更支持的解释是冷焊或勉强焊点。

补救是机械性的，不是电气性的：回流并放大检查全部 24 个焊点，找立碑的元件、同一对两个焊盘之间的桥连，以及只是搭在焊盘上而没有浸润的焊点。

这些操作都没有破坏性。不完美的结果只是让链路协商得更低，不会损坏显卡，而且在修焊点期间，卡会在它协商出的任何宽度下继续工作。没有尝试次数限制，也没有需要重置的状态。

## 验证

用 **`LnkSta`** 验证，绝不要用 `LnkCap`。`LnkCap` 是宣告的能力，可能在链路协商到更低时仍显示 x16（或 Gen2）。这个坑被指为大多数经不起推敲的「成功了」说法的来源。

```bash
# 1. Find the card. Both SKUs enumerate as GA100 [CMP 170HX] (rev a1).
lspci -nn | grep -i nvidia
#   e.g. 0a:00.0 3D controller [0302]: NVIDIA Corporation GA100 [CMP 170HX] [10de:20c2] (rev a1)

# 2. The authoritative read: link status on the endpoint.
sudo lspci -s 0a:00.0 -vvv | grep -E 'LnkCap:|LnkSta:'

# 3. Kernel's own view, no root required.
cat /sys/bus/pci/devices/0000:0a:00.0/current_link_width   # want 16
cat /sys/bus/pci/devices/0000:0a:00.0/max_link_width       # 16
cat /sys/bus/pci/devices/0000:0a:00.0/current_link_speed   # 2.5 GT/s unless Gen2 is also applied

# 4. Driver's view.
nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.gen.max,pcie.link.width.current --format=csv
```

预期状态转换：

| 状态 | `LnkSta` | `nvidia-smi` gen.cur, gen.max, width |
|---|---|---|
| 出厂：无改装、无解锁器 | `Speed 2.5GT/s, Width x4 (downgraded)` | `1, 1, 4` |
| 电容改装，未装解锁器 | `Speed 2.5GT/s, Width x16` | `1, 1, 16` |
| 已装解锁器，无电容改装 | `Speed 5GT/s, Width x4 (downgraded)` | `2, 2, 4` |
| 电容改装 + 解锁器 | `Speed 5GT/s, Width x16` | `2, 2, 16` |

注意：一旦 24 颗元件全部就位，宽度字段上的 `(downgraded)` 后缀就会消失——这是最清晰的改装前后信号。

> [!TIP]
> **速率字段上的 `(overdriven)` 是正常的**
>
> 取决于 Gen2 的应用方式，`lspci` 可能打印 `LnkSta: Speed 5GT/s (overdriven), Width x16`。这个后缀只是表示 `LnkSta` 报告的速率高于 `LnkCap` 宣告的速率——在不重写宣告能力的情况下强制链路速率时恰好如此。这不是错误，也不是不稳定。

完整验证流程见 [Verify](../procedures/verify.md)，故障排查见 [Troubleshooting](../procedures/troubleshooting.md)。

> [!TIP]
> **在负载下测试**
>
> 很多平台在无流量时会把链路降到空闲。如果宽度或速率读数看起来不对，在带宽测试期间重新读，别在待机时读。

## 这项改装换来什么

| 配置 | 实测主机带宽 | 备注 |
|---|---|---|
| Gen1 x4（出厂） | **约 0.85 GB/s**（发送 0.80、接收 0.84） | OpenCL-Benchmark / clpeak |
| Gen1 x16（仅电容改装） | **2.88 GB/s**，平稳、零错误 | 标称约 4 GB/s；差距归因于 PCIe 1.1 信令开销 |
| Gen2 x4（仅软件） | **发送 1.68 GB/s / 接收 1.71 GB/s** | OpenCL-Benchmark，一张存档截图，未改装卡；安装脚本独立预测「约 0.85 到约 1.7 GB/s，正好 2 倍」。置信度中 |
| 改装过电容但协商到 x8 的卡上从 Gen1 → Gen2 | **1.67 → 3.24 GB/s** | 一次 A/B 对比，单卡，Asus Prime Z370 / i3-8100 / 8 GB RAM。置信度中。这**不是** Gen2 x4 的结果：3.24 GB/s 超过了 Gen2 x4 约 2.0 GB/s 的天花板，因为卡跑在 x8 |
| Gen2 x16（两者都做） | **6.63 至 6.67 GB/s** | `ocl_pcie_bw`；nvtop 在 `PCIe GEN 2@16x` 显示 TX 7.061 GiB/s |
| Gen2 x16（两者都做），第二套机 | **5.97 GB/s** host-to-device，4 张卡完全一致 | 四卡项目，用 `MAASJ105SB7224KFCA01`，CUDA H2D，`MaxPayload` 256 字节。与 6.63 GB/s 那套的差异在主机侧；两者都处于 PCIe 2.0 x16 对 8 GB/s 天花板的正常区间。见 [实测报告](#field-report-four-cards-at-gen2-x16) |

说一句为什么即使速率更容易拿到、通道数仍然重要：平台通道预算独立于带宽限制卡的数量。纯软件的 Gen3 x4 解锁完全不需要焊接，这正是 Gen3 x4 成为社区下一个目标的原因。频道里有人说它和 Gen2 x16 速率相当，但算数不支持这个说法：Gen3 x4 大约 3.9 GB/s（8 GT/s、128b/130b、四条通道），而 Gen2 x16 是 8 GB/s，所以它更接近 Gen1 x16。无论哪种，「通道就是通道」，对任何想在一台主机里塞很多卡的人来说都是如此。见 [PCIe Gen3 and Gen4](../frontier/pcie-gen3-gen4.md)。

链路宽度对推理吞吐有什么影响、没什么影响，见 [LLM inference](llm-inference.md) 和 [Performance](performance.md)。流水线并行下的卡间流量可以忽略（5120 隐藏维度的模型每 token 每跳移动 10,240 字节，所以大约需要 25,000 token/s 才能塞满一条 PCIe 1.0 通道），而张量并行和专家并行即使在 PCIe 2.0 x16 下也被判为不可行。

### 软件代码树里与此无关

电容改装对解锁器不可见，这是被验证过的否定结论，不是假设。出货的 `master` 或 12 个未发布分支中没有任何文件包含字符串「capacitor」「AC coupling」或「solder」，也没有任何通道宽度寄存器。对完整 git 历史 grep 一遍也是空。出货的 `0007-pcie-gen2.patch` 只操作链路**速率**寄存器。

> [!NOTE]
> **出处更正**
>
> 一个广泛流传的说法称，随附的解锁 README 把该限制记录为「PCIe width is x4 (not x16): This is a hardware limitation of the CMP 170HX -- missing AC coupling capacitors on lanes 4-15.」**出货的 `README.md` 里没有这样的文字**，任何分支或 git 历史的任何节点也都没有。技术论断本身是真的、证据充分；只是「出自随附 README」这个归因是错的。它很可能源自某份第三方指南。

## 实测报告：四张卡达成 Gen2 x16

一位社区成员用每张 24 颗 Taiyo Yuden `MAASJ105SB7224KFCA01`（220 nF、6.3 V、X7R、0402）改装了四张 CMP 170HX 卡，并提供了照片和日志。四张全部训练到 **PCIe 2.0 x16**，并持续运行四卡 LLM 推理，**PCIe 错误为零**。这是继 2026-07-26 的单一观察之后第二套达成 Gen2 x16 的独立机器，也是第一套多卡、多板卡版本、带任何错误遥测的。

> [!TIP]
> **只装了电容**
>
> 没有刷任何 VBIOS：四张卡都仍报告出厂 `92.00.6D.00.0A`。没有补 VRM 相位、没有搬 strap 电阻、没有加备份闪存芯片，板子上其他任何焊盘都没动。流传的 `a100-unlock.pdf` 物料清单列了 Winbond 闪存芯片和若干其他元件；**x16 一个都不需要**。这直接证实了 PDF 作者自己后来的说法：对通道宽度而言，只有 PCIe 通道上的元件要紧。

### 板卡

两个不同丝印版本被改装且结果相同：`180-11001-DAAA-B15` 和 `180-11001-DAAA-B35`，都带板卡料号 `699-11001-0108-600 G`。**B35 版本此前没有记录。** 四张卡都是 8 GB SKU，运行 64 GB 显存解锁，因此报告 65536 MiB。

### 链路状态

四张卡、同一台主机，电容改装加打了补丁的驱动（带 `NVreg_RegistryDwords="RmForceEnableGen2=1;RMPcieLinkSpeed=0x2"`）：

```text
LnkCap:  Port #0, Speed 2.5GT/s, Width x16, ASPM not supported
LnkSta:  Speed 5GT/s (overdriven), Width x16
LnkCap2: Supported Link Speeds: 2.5GT/s, Crosslink- Retimer- 2Retimers- DRS-
         MaxPayload 256 bytes, MaxReadReq 512 bytes
```

```text
0000:03:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:04:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:88:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
0000:89:00.0: width=16 speed=5.0 GT/s PCIe maxwidth=16
```

注意：在这套机器上，注册表 DWORD 路线只移动了 **`LnkSta`**；`LnkCap` 仍宣告 2.5 GT/s，所以 `lspci` 打印的是 `(overdriven)` 而不是干净的 `5GT/s`。分支时代的 Gen2 代码有份更早的报告显示 `LnkCap: Speed 5GT/s`。两种呈现都是可用的 Gen2 链路。关键看 `LnkSta`，特别是 `Width x16` 不带 `(downgraded)` 后缀。

### 错误遥测

90 分钟持续四卡推理后的内核 AER 计数器：

```text
0000:03:00.0: RxErr 0 BadTLP 0 BadDLLP 0 Rollover 0 Timeout 0 NonFatalErr 0 CorrIntErr 0 HeaderOF 0 TOTAL_ERR_COR 0
0000:04:00.0: RxErr 0 BadTLP 0 BadDLLP 0 Rollover 0 Timeout 0 NonFatalErr 0 CorrIntErr 0 HeaderOF 0 TOTAL_ERR_COR 0
0000:88:00.0: RxErr 0 BadTLP 0 BadDLLP 0 Rollover 0 Timeout 0 NonFatalErr 0 CorrIntErr 0 HeaderOF 0 TOTAL_ERR_COR 0
0000:89:00.0: RxErr 0 BadTLP 0 BadDLLP 0 Rollover 0 Timeout 0 NonFatalErr 0 CorrIntErr 0 HeaderOF 0 TOTAL_ERR_COR 0
```

任何一张卡都可纠正错误为零、无致命错误。如果交流耦合网络勉强达标或存在仍能训练出 x16 的冷焊点，在持续流量下预期会积累 `BadTLP` 或 `RxErr`。超过 90 分钟的烤机还没有测过。

### 带宽

| 测量项 | 结果 |
|---|---|
| Host-to-device，CUDA，每卡 | **5.97 GB/s**，四张一致 |
| `MaxPayload` | 256 字节（本机实测最优；128 字节会损失吞吐） |
| `MaxReadReq` | 512 字节 |

PCIe 2.0 x16 经 8b/10b 编码后的天花板是 8 GB/s，5.97 GB/s 约为 75%，算上 TLP 和 DLLP 开销后属于正常区间。它低于第一套 Gen2 x16 机器记录的 6.63 至 6.67 GB/s；差异在主机侧（根复合体和芯片组不同），不是改装本身的属性。同样的 75% 比例也出现在 Gen1 x16 的 2.88 GB/s 对 4 GB/s 天花板中。

## 拆解

装水冷头前、够到 SPI 闪存芯片前，以及（对已组装卡）做任何板级返工前都需要拆解。紧固件是 **Torx T10 和 T15**。

1. 拆下 4 颗 PCIe 安装支架螺丝并**保留支架**：它在装水冷头时要复用为垫片。另一侧的支架不需要拆。
2. 翻面，拆下背面 10 颗螺丝。
3. 再翻回来，打开前面板；PCIe 支架随之取下，露出散热器。
4. 拧下右上角固定电源线和接口的支架螺丝。
5. 用塑料撬棒把较硬的电源线从背板上撬开。线不脱离，板子就动不了。
6. **最难的一步。** PCB 不能垂直抬起，因为 PCIe 接口插在背板的槽里。把板子水平滑离接口几毫米，然后一边继续水平移动一边抬起。这一步有记录显示第一次尝试就难倒了一个知名硬件频道。
7. 拆下 PCB 背面 4 颗弹簧螺丝并**保留 4 个垫圈**。它们不能与副厂水冷头附带的塑料垫圈混用。
8. 用塑料撬棒从无元件的边缘把散热器撬下来，托住它，别让它砸到 PCB 上。

规划时有用的物理尺寸：PCB 长 27 cm，算上 I/O 挡板和插上的 EPS 接口全长 29 cm；散热器螺栓孔距 57 × 68 mm 中心对中心（68 mm 垂直、57 mm 水平）；核心封装约 55 × 55 mm。

## 散热改装

操作层面的细节见 [Cooling](cooling.md)；本节只讲物理工作。

### 水冷头

**Bykski `N-TESLA-A100-X-V2`** 适配 A100 40 GB、CMP 170HX 和 A30 24 GB 板卡，使用标准 G1/4 接头。**必须**是 V2（全金属）版本；早期非 V2 版本用透明亚克力。不要和 A100 **80 GB** 冷头搞混，那个不兼容。唯一有记录的安装给出这些实用警告：冷头发货不带说明书，只有两句在线快速上手指南，附带的内六角扳手尺寸不对，所以备一套公制内六角。A100-PCB 水冷头适配并会露出 NVLink 金手指。

> [!CAUTION]
> **放下冷头前，盖住每一处未贴片的 IC 焊盘**
>
> 水冷头安装中最致命的一个错误是让未贴片 IC 焊盘裸露。冷头的金属接触柱可能跨接裸露的铜焊盘，**永久烧毁显卡**。因为 170HX 是去料版 A100 板卡，裸焊盘比真正的 A100 多得多，上水冷头相应更危险。
>
> 垫住任何接触柱够得着的焊盘：ASIC 左右两侧的 DrMOS MOSFET；ASIC 左下和右下；核心右侧电感与电容之间的 PMIC；以及核心左侧 3.3 µH 电感下方的那两颗 PMIC。导热硅脂（豌豆大小）只涂在 GPU/HBM 铜散热片上。
>
> 置信度说明：这条指示是有记录的流程，机理也成立，但因果归因基于一张在安装约一小时后死掉的卡。作者的首要怀疑与既有的矿场磨损故障、以及一个「漏装支架」理论竞争。从未被最终定位。反正垫上。

装配细节：

- 复用拆解第 7 步存下的 **4 个原装垫圈**，不要用冷头附带的塑料垫圈，但用**冷头的弹簧螺丝**，别用原装螺丝。
- 先装一颗弹簧螺丝，然后把电源接口插进冷头的槽位。接口固定盖（件 4）必须先拧下两颗六角螺母（件 5）才能取下。然后装剩下 3 个垫圈和螺丝。
- **把原装 PCIe 插槽支架装回左侧 PCB 与背板之间**，作为垫片。它的额外高度决定了背板与板子之间的间距。
- 背板用四颗 **9.5 mm M2** 螺丝固定，先两颗，再两颗。
- 最后在加冷却液之前做一次 **15 分钟加压检漏**。

原装散热器上的导热界面：主要区域 1.5 mm 软垫、电感上 3 mm 软垫，核心上用液态导热膏或液态导热垫。主区域还有一个「2 mm」的说法被提出，但前面带着「我觉得」，置信度较低；T10/T15 批头有双方报告互相印证。

### 风冷

57 × 68 mm 的螺栓孔距与 RTX 4080 散热器或 socket-478/370 扣具接近，允许改装；有人报告 4080 散热器「勉强」能装。坊间流传两个打印方案：

- 常见的 3D 打印导流罩（`CMP_170HX_Fan_Shroud_Fixed.stl`、`CMP_170HX_Dual_Shroud_Fixed.stl`）靠摩擦固定，时间长了会掉，壁厚太薄，即使 PETG 也很脆弱。只有 STL，想容易地修改需要 STEP 文件。
- Level1Techs A 系列涡轮风扇转接件（`l1 a100 blower.stl`，52.3 KB，发布于 2023-07-05）是免支撑打印件，用螺丝固定在显卡远端现有的螺丝孔上，供电接口旁带一个斜向低位段，方便手指伸入。耗材、打印参数、气流方向和耐用性曾在帖子里被追问，从未得到回答。

> [!WARNING]
> **无论装什么散热器，都必须顺带冷却 VRM**
>
> 只覆盖核心的散热器会让供电级无人照看。一份有争议的现场报告描述：卡在长时间挖矿后反复炸掉背面一个元件，怀疑是操作者只盯着核心传感器（约 56 °C），却在一个带宽密集型负载上让 VRM 过热。一位资深长期用户完全否认这种故障模式。尚无定论，但设计原则照旧成立。

> [!NOTE]
> **未解决问题**
>
> V100 均热板水冷头能适配 170HX 吗？问过，从未实测。买之前把 57 × 68 mm 螺栓孔距和 55 × 55 mm 核心尺寸对照冷头规格书核对。相关的已知可用数据：SXM3 散热器经过小幅修改可与 SXM2 互换。注意：170HX 卡身很厚，通用 NVIDIA 涡轮风道可能装不上。

## 电源接口与供电改装

显卡采用单个 **EPS 8-pin**，不是 PCIe 8-pin。大多数电源自带的 EPS 线卡扣过大物理上装不进，所以 **2× PCIe-8-pin 转 EPS 转接线**是常见解法。模组 EPS12V 线必须**两端**都是 4× 12 V 和 4× GND，一颗优质针脚只能承载约 70 到 80 W。DevCap 报告的插槽功耗上限是 75 W；TDP 是 250 W，而 300 W 不是软件上限：出厂固件下最大值等于默认值，所以 `nvidia-smi -pl` 只能把卡下调到 100 W 到 250 W 之间。只有 NVIDIA 发布的 300 W「OC 挖矿」VBIOS 能抬高上限，而且只在带该 VBIOS 的卡上。见 [Power and PSU](power-and-psu.md)。

### 分流电阻改装（Shunt mod）

> [!CAUTION]
> **从未执行，从未测量**
>
> 恢复完整 A100 TDP 预期只是一个简单的分流电阻改装，而不是固件改动。**语料中没有人执行或测量过。** 这个判断来自一位有经验的硬件改装者的专业意见，对这一类卡是合理的，但分流电阻位置、电阻值、最终功耗数字和热后果全都未知。也有人提出软件或 VBIOS 路线实现 400 到 500 W 上限，作为不适分流电阻改装的人的选择，同样从未实现。在这张卡上尝试分流电阻改装是无人区，且有明显的毁卡路径。

### 未贴片的 4-pin 焊盘

PCB 上有一个未贴片的 4-pin 焊盘，实测带 12 V，被怀疑是风扇接口。

> [!NOTE]
> **未解决问题**
>
> 没人确定配套母座零件是什么、有没有转速反馈线、是否支持 PWM 控制。想要它是因为它能让每张卡独立控制风扇，不需要外部控制器。下一步：在待机和负载下用示波器看剩下两根针，并在泄露的原理图上追线。

## Strap 电阻

板卡在左上角去耦电容附近带有五对 strap 电阻：十个焊盘对应五组 strap，元件无标号，通常是 100 kΩ 0402，拉到 0 V 或 1.8 V。每组 strap 是一颗电阻加一个空焊盘，所以在两个位置之间移动元件就翻转该 strap 位。从 PCB 上从左到右读：

| Strap | 位号 | 功能 |
|---|---|---|
| Strap1 | R986, R987 | RAMCFG[1] |
| Strap0 | R989, R990 | RAMCFG[0] |
| Strap3 | R993, R994 | VGA_DEVICE |
| Strap4 | R999, R1000 | PCIE_CFG |
| Strap2 | R1004, R1005 | RAMCFG[2] |

R1004 和 R1005 是**同一个** strap 位置的两个可选焊盘，不是两颗独立电阻。第六组 strap **DEVID_SEL，位于 R240/R241**，出自同一来源，但从未在物理板上找到。

出厂模式：A100 40 GB 和 170HX 10 GB 共享 `LLLLH`；170HX 8 GB 是 `HHLLH`。

> [!CAUTION]
> **有一个 strap 模式会让主机点不亮**
>
> 10 GB 卡上的 `LLHHH` 造成**完全无法 POST**。把 A100 的完整 strap 配置复制到 170HX 上导致**开机检测不到卡**。strap 实验原则上可逆，但在把元件移回去之前，你可能已经失去一套能用的系统。

> [!NOTE]
> **未解决问题**
>
> Strap3（VGA_DEVICE，R993/R994）和 Strap4（PCIE_CFG，R999/R1000）实际做什么？2026-07-26 问过，从未回答。存在一个偶然数据点：一位本想移 R1004 的测试者实际移的是 Strap4，把 `LLLLH` 变成了 `LLLHH`，报告没有内存影响。PCIe 能力协商是否变化从未被测量。下一步：刻意重复那个实验，并抓取前后的 `lspci -vv` LnkCap/LnkSta。

> [!NOTE]
> **未解决问题**
>
> 在物理板上定位 R240/R241（DEVID_SEL）。设备 ID 是出货驱动据以判断显存几何的关键，而 `OPT_DEVID_SW_OVERRIDE_DIS @ 0x00820584 = 0x00000001` 封死了所有改变它的软件路线。搜索启发式，听起来合理但从未大规模试过：在 PCB 上带 200 系位号、且位号小于 500 的那一面，找一颗紧挨着空焊盘的电阻。问商用 AI 助手得到了一份信心满满、但完全编造的板卡拓扑，被记录为一个警示数据点。

## VBIOS 刷写硬件

这张板**没有操作系统级的刷写路径**。写 VBIOS 意味着直接把烧录夹夹到 SOIC 元件上，这需要拆散热器，但用烧录夹写入不需要改板上的任何无源元件。

> [!CAUTION]
> **上电前先写保护**
>
> 刷写失败 `0xBADF3000`、板子读不了闪存，是因为**重新上电前没有给 SPI 芯片写保护**。恢复方法是直接用烧录夹重刷 SOIC 并设置写保护。相关症状是 RM init 适配器失败。置信度：中（来自一位在这类板上做过 SOIC 和 VRM 工作的人；报告的用户随后不久就救回了卡）。见 [Recovery](../procedures/recovery.md) 和 [VBIOS](../hardware/vbios.md)。

流传的硬件恢复物料清单里的 Winbond BIOS 芯片是**备份 VBIOS 芯片**，用于从一次坏刷写中恢复。它不是 PCIe 或显存解锁的一部分。

## 任何焊接都修不好的东西

这些边界要么烧进了熔丝，要么烧进了封装，它们框住了本页的所有硬件想法。细节见 [Fuses and OTP](../hardware/fuses-and-otp.md)。

| 限制 | 机制 | 为什么焊接没用 |
|---|---|---|
| SM 数量 70（5 个 GPC、35 个 TPC、CC 8.0） | `OPT_GPC_DISABLE 0x00820350` OTP | 每个 per-GPC `CTRL_OPT`（`0x00820838 + i*4`）和 `RECONF_OVR`（`0x00820a40 + i*4`）都已经读作 `0x00000000`；枚举出的数量恰好等于熔丝下限。没有任何东西被藏着 |
| 显存容量上限 | `FUSE_FBP_DISABLE 0x00820364`、`FUSE_FBPA_DISABLE 0x00820368`、`FUSE_FBIO_DISABLE 0x0082036c`、`ROP_L2_DISABLE 0x008202c4` | 对应的 DEFECTIVE 寄存器全部读作 `0x0`，所以不存在真实硅片缺陷，只有一张生效的禁用掩码；往 DISABLE 寄存器写 0 移不动它们 |
| 死掉的 HBM 堆栈 | 键合在**硅中介层**上，不在 PCB 上 | 回流焊没用。一位成员用热风枪在多种温度下花了好几个小时处理几张 HBM2 GPU，毫无成功。HBM 堆栈内部也含熔丝，坏的裸片可以在堆栈内部被永久熔断掉 |
| NVLink | `FUSE_NVLINK_DIS` 加上未贴片的接口 IC | 边缘金手指物理存在，A100 水冷头也会露出它们，但让 NVLink 起来既需要缺失的 IC，又需要一条已置位的熔丝。中介层本身很可能也带 eFuse。见 [NVLink](../frontier/nvlink.md) |
| ECC | 已熔断关闭，无杠杆、无遥测 | 见 [ECC](../frontier/ecc.md) |
| 显示输出 | 板上没有显示硬件 | 某些 CMP 板上有显示焊盘，但需要「一大堆缺失的 SMD 元件」；在 170HX 上记录为永久缺失 |
| 设备 ID | `OPT_DEVID_SW_OVERRIDE_DIS 0x00820584 = 0x00000001`；DEVIDA/DEVIDB 熔死在片内，由 strap 锁存选择 | 软件无法覆盖，选择 strap 也从未被定位 |

对早期一句笼统的「硬件解锁不可能」的准确更正：**硬件改装移不动熔断边界，但可以恢复被去料的 PCB 特性。** 电容改装就是这种区分兑现的地方。

## 相关型号（CMP 100-210）

**CMP 100-210**（V100 级部件）改 V100 或 Titan V **既**要搬 strap 电阻**又**要强制刷写，按这个顺序：在 strap 阵列上，把现有电阻从底部焊盘移到顶部焊盘得到 `HHLLHH`（出厂报告为 `HLLLHH` 或 `HLLHHH`），然后用 `omgvflash` 强制刷官方 Tesla V100 16 GB VBIOS。不需要不同的电阻值，只需要搬位置。只刷写是测过的，**会失败**：卡能枚举但设备 ID 不变，所以 Linux 驱动把它当作 CMP 100 绑定，加载错误的二进制 blob。置信度：完整流程为中（一个人、有照片、多台成功，日志内没有第二方完成）；「只刷写不够」这一半为高，它被直接测试过。

> [!WARNING]
> **电容改装的结果不能平移到 CMP 100-210**
>
> 170HX 的通道数纯粹是电容问题（只焊接、完全不用软件就能得到 x16，多方确认）。而 CMP 100-210 上有一份相反的报告说，在 PCIe 插槽附近加电容**不能**在那里解锁 x16，还说那张卡的通道数同样受软件门控。不同的硅片；答案没必要一致，但 170HX 的说法在流传时没带这个限定。

> **买家警告：两样不同的东西都卖约 1500 美元**
>
> 另一家**不同**供应商的约 1500 美元档是**翻新，不是电容改装**。问清楚你被卖的是哪一档。一些闲鱼列表还额外收取捆绑的「破解系统盘」费用，那是一份预装好的解锁启动镜像。

### 本地维修店更便宜，只要找得到愿意接活的

深圳的服务价不是地板价。一位装机者在一家本地电子维修店做了全部卡片，**每张约 50 美元**，约为 1000 元服务费的三分之一，没有运费，卡也不出国。

难的不是焊接，是找到愿意干的人。那位装机者被**十多家店**拒绝，才找到一家愿意不争论、直接贴件的。做好被拒的准备：店家通常想先诊断卡、质疑缺电容不是真正的故障，或者拒绝修不是他们卖出的硬件。按板卡维修标准，这活儿本身平平无奇，正因如此拒绝率才惊人。

由此得出的建议（不是来自任何测量）：

- 按描述下单，别按解释下单。「在这批标好号的焊盘上贴 24 颗 0402 电容，元件自备」是可以报价的活儿。解释它解锁矿卡的 PCIe 通道，就会招来关于它是否有效的争论——拒绝就是这么开始的。
- 电容自己备。全套只需几美元，还消除了任何采购异议。见[物料清单](#bill-of-materials)。
- 板级微焊接店和手机维修店比普通电脑维修店更合适。它们本来就有热风枪、显微镜和助焊剂，0402 活儿对它们很常规。
- 接受店家不为结果保修。它也没法保：链路能否训练出 x16 取决于卡本身，不只是焊点。

每张 50 美元同时压过了 1000 元的服务费和约 300 美元的改好卡溢价。
